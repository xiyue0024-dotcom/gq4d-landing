01拦截链路总览

六个板块串行，前两个负责「采集与入口」，中间两个负责「判定」，后两个负责「处置与运营」。

M1信号采集设备ID、指纹哈希、自动化信号、IP/ASN、行为轨迹
→
M2入口校验nonce、来源白名单、边缘限流、频率控制
→
M3名单比对共享黑名单只读 + 本地名单 + 跨号关联
→
M4三层判定硬拒 → 评分 → 挑战；短窗聚集整批封禁
→
M5处置表现软拦 / 硬拦 / 证据落表 / 自动入本地名单
→
M6运营闭环管理端改号、评分分布、告警、90 天归档
关键原则：账号只在判定通过时下发；拒绝回执不含账号、不含原因；前端只显示统一的印尼语「网络繁忙」话术，规则、阈值、名单一律不下发。

02板块明细

每个板块的职责、关键参数与失败策略。

M1

信号采集

index.html · collectSignals / buildProbe

在浏览器本地计算，只上报哈希与布尔值，不上报原始指纹、不发任何外部请求。

  • 设备标识：localStorage UUID（分身应用会隔离存储，故只作辅证）
  • 指纹哈希：UA、语言、屏幕、时区、CPU/内存、平台 + canvas + WebGL → FNV-1a 32bit
  • 自动化痕迹：navigator.webdriver、HeadlessChrome UA、window.chrome 缺失、plugins=0、eval.toString().length、软件渲染
  • 一致性矛盾：Intl 时区 vs UTC offset、language vs languages[0]、屏幕异常值
  • 行为：指针/触摸轨迹次数、点击前 2 秒是否有移动、填表耗时、页面停留时长、isTrusted
  • 网络：公网 IP、ASN、归属组织、国家（来自自有 Worker）
零第三方依赖 异步取 IP，不阻塞 失败即忽略 in-app 浏览器白名单
M2

入口校验

Cloudflare Worker · /api/gate

防止绕过页面直接调用判定端点，并挡住洪泛。

  • 一次性 nonce：页面加载时签发，HMAC 签名、TTL 10 分钟、绑定 device_id，重放无效
  • 来源校验：Origin / Referer 白名单（Apps Script 拿不到请求头，所以放在边缘）
  • 边缘限流：按 IP 10 次/分、/24 网段 60 次/分、ASN 600 次/分；超限返回同一张「繁忙」页
  • 判定通道：同源 POST /api/gate → Worker 转发 Apps Script，浏览器不再直连后端
解决「端点当预言机」 保护 Apps Script 配额 隐藏后端地址
M3

名单比对

3_Risk.gs · loadBlacklist / linkedBlackHit

号码直查 + 设备/指纹跨号反查，覆盖「换号重进」。

  • 共享黑名单：只读签到系统的 Daftar Hitam，绝不写入
  • 本地名单：本系统自建，硬拒时自动写入；读取时与共享表合并、本地优先
  • 状态口径：Studio / Rekan = 黑，Pantau = 观察，Aman = 白名单豁免
  • 跨号关联：新号码与历史黑名单号码共用设备 / 指纹 / IP 即命中
共享表只读 本地表可写 空状态按黑处理
M4

三层判定

3_Risk.gs · scoreVisit / markWindows

先看硬拒项，再算评分，最后按分数决定放行、挑战或拒绝。

  • 第一层 硬拒：命中任一项直接拒绝，不进入评分
  • 第二层 评分：0–100 加权累加，封顶 100
  • 第三层 挑战：评分落在中档时要求完成轻量 PoW，未完成按拒绝处理
  • 短窗聚集：10 分钟内同设备/指纹/IP 出现 ≥3 个不同号码 → 整批封禁（CacheService，TTL=窗口剩余）
判定在服务端 阈值不下发 计数走缓存
M5

处置表现

2_Gate.gs · decide / writeBlockLog

让被拦者无法判断自己为什么被拦，也让运营能事后复核。

  • 软拦（默认）：转圈 2.8–4.8 秒随机，显示统一印尼语繁忙话术，可重试
  • 硬拦（管理端可切）：同一话术 + CTA 置灰，完全禁止跳转
  • 延迟对齐：放行与拒绝施加相近延迟，防计时侧信道
  • 证据落表：时间、号码、命中类型、关联号码、评分、命中项、模式、原因
  • 自动入本地名单：硬拒即写入，状态 Studio，备注写命中原因
统一话术 拒绝不含账号/原因 评分入库
M6

运营闭环

4_Admin.gs · 管理端

改号即时生效，异常可被发现。

  • 改号：管理页改 WA_NUMBER，下一次请求立即生效，无需改 HTML、无需重新部署
  • 切换软/硬拦、告知模式
  • 评分分布、按原因分布、Top ASN、Top 设备、最近拦截
  • 告警：10 分钟内拦截 >30 次或 ASN 集中度异常时推送
  • 归档：访问日志 90 天后移入归档表
改号即时生效 配额熔断 90 天归档

03第一层：硬拒项

命中任一项直接拒绝，不进入评分。已排除 in-app 浏览器（FBAN / Instagram / TikTok / WhatsApp WebView）。

硬拒项判定依据误伤风险
WebDriver 标记navigator.webdriver === true 且 UA 不在 in-app 白名单极低
无头浏览器 UAUA 命中 HeadlessChrome / PhantomJS / Lightpanda极低
无窗口尺寸outerWidth === 0 或 outerHeight === 0低
蜜罐字段被填隐藏输入框 website 有值极低
合成点击点击事件 isTrusted === false极低
号码号段非法非 62 + 印尼有效移动号段，或长度不符低（需维护号段表）
同设备多号同 device_id 90 天内 ≥2 个不同号码低（分身可绕过）
同指纹同 IP 多号同 fingerprint + 同 IP 键 24h 内 ≥2 个不同号码中（同 WiFi 会被拦，符合口径）
同点击 ID 多号同 fbclid / gclid / utm_content 24h 内 ≥2 个不同号码低

说明：in-app 浏览器普遍缺 window.chrome、plugins 为 0，因此这类信号只进评分，不做硬拒。

04第二层：评分权重

0–100 累加后封顶。单项分值代表「该信号单独出现时的可疑程度」，组合后过线即拦。

评分项权重触发条件
黑名单跨号关联60新号码与黑名单号码共用设备 / 指纹 / IP
同 IP 键多号40同一 IP 键 24h 内 ≥2 个不同号码（已拍板）
国家与时区不一致30如 IP 国家 ID 但时区为 Asia/Shanghai
机房 ASN / 组织25ASN 或组织名命中机房、VPS、托管商关键词
填表耗时 <3 秒25首次输入到提交的间隔
软件渲染25WebGL 命中 SwiftShader / llvmpipe / Software
同号码多设备25同一号码 24h 内出现在 ≥3 个设备
点击前无指针轨迹20点击前 2 秒无 mousemove / touchmove
页面停留 <3 秒20页面加载到点击 CTA 的间隔
语言非 id / en15navigator.language 不在白名单
屏幕为默认值15800×600 或 1280×720
姓名疑似乱码15纯数字、单字符、重复字符、异常长度
桌面端 plugins=010非 in-app 的桌面 UA 但插件为空
硬件参数异常10hardwareConcurrency ≤2 或 deviceMemory ≤1
五题同序号10q1–q5 全部选同一位置

权重为初始值，上线后按「拦截准确率」与「误拦申诉」调整；所有阈值仅存服务端。

07处置矩阵

同一套话术，三种不同的后台行为。

ALLOW · 放行

下发账号，前端延迟后打开 wa.me。日志按 10% 抽样写入，降低配额压力。

CHALLENGE · 挑战

前端完成轻量 PoW 后重新判定；通过则放行，失败或超时按拒绝。用户侧仍显示「网络较慢」。

DENY · 拒绝

永不下发账号、永不打开 wa.me。软拦 2.8–4.8 秒后提示繁忙；硬拦则置灰 CTA。写证据 + 自动入本地名单。

失败策略：后端异常、超时、脚本加载失败一律按 拒绝 处理（fail-closed）。宁可少一条线索，也不让账号在不确定状态下暴露。
